# stock-screener

국내 주식·ETF를 **조회하고 걸러내는** 스크리너. 직장인이 직접 쓰려고 만들었다.

API 키 없이 돌아가고, 출력은 **마크다운 표 + CSV**다. 대시보드가 아니라 **판단 재료를 만드는 도구**다.

```bash
pip install streamlit pandas
streamlit run app.py          # → http://localhost:8501
```

## 만들면서 알게 된 것 — ETF 총보수는 비용 지표가 아니다

국내 S&P500 ETF는 운용사끼리 보수 인하 경쟁을 하면서 **명목 총보수를 0.00x%까지 내렸다.**
그런데 **총보수는 운용·판매·수탁·사무관리 보수만**이고, 실제 비용에는 이게 더 붙는다.

- **기타비용** — 회계감사비, **지수 사용료**, 해외자산 보관수수료, 예탁원 결제보수
- **매매·중개수수료** — 지수 추종 리밸런싱 거래비용

운용사 홈페이지는 보통 **총보수만** 공시한다. 그래서 숫자가 뒤집힌다.

**동일 지수(S&P500) 추종 ETF 10종 실측 (2026-10-07):**

| 종목 | 총보수 % | 1년 수익률 % | 실질차 %p |
|---|---|---|---|
| RISE 미국S&P500 | 0.0047 | **12.45** | 0.00 |
| ACE 미국S&P500 | 0.0047 | 12.25 | −0.20 |
| KODEX 미국S&P500 | 0.0062 | 12.22 | −0.23 |
| TIGER 미국S&P500 | 0.0068 | 12.20 | −0.25 |
| **SOL 미국S&P500** | **0.0047** | **11.85** | **−0.60** |
| 1Q 미국S&P500 | 0.0055 | 11.64 | −0.81 |

**SOL과 RISE는 총보수가 똑같이 0.0047%(업계 최저)인데 1년 수익률이 0.60%p 차이난다.**

같은 지수를 추종하므로 그 차이는 **기타비용 + 추적오차**다. 총보수만 보면 알 수 없다.

> **같은 지수를 따라가는 상품끼리는 「1년 수익률 차이」가 실부담비용의 실측값이다.**
> 공시는 "작년에 얼마 떼갔다"를 말하고, 수익률은 "그래서 내 돈이 얼마 남았다"를 말한다.

그래서 `compare_etf.py`는 **`실질차_%p`** 컬럼을 만든다 — 후보 중 1년 수익률 최고를 0으로 두고 나머지를 상대 표시한 것.

## 기능

### ETF 스크리너
- 상장 ETF **전체 1,171종** 조회 (시세·NAV·순자산·수익률)
- **파생·테마 변종 제외 필터** — `커버드콜 / 채권혼합 / 레버리지 / 인버스 / 액티브 / ESG / 섹터 / 환헤지` 등 16종 키워드
  → "S&P500"으로 검색하면 30종이 걸리는데 **순수 광범위 지수는 6종뿐**이다. 나머지는 전부 변종
- 최소 순자산 필터 (규모가 작으면 청산·유동성 리스크)
- 괴리율 자동 계산, 후보 다중 선택 비교

### 종목 스크리너
- KOSPI **2,483종** / KOSDAQ **1,823종** 시가총액 순

### 재무 분석
- **연간·분기 재무제표** — 매출·영업이익·순이익·영업이익률·ROE·부채비율·당좌비율·유보율·EPS·PER·BPS·PBR·주당배당금
- 매출·이익 추세, 수익성·안정성 차트
- **컨센서스 컬럼 경고 배너** (아래 주의사항 3번)

### 포트폴리오
- 코어/새틀라이트 비중, 섹터별 상한 초과 판정
- **포지션 사이징** — `포지션 = (총자산 × 1회 최대 손실률) ÷ 손절 거리`
  "확신"이 아니라 **손절 거리**가 금액을 정한다

## 데이터 소스 (전부 키 불필요)

| 소스 | 얻는 것 |
|---|---|
| `finance.naver.com/api/sise/etfItemList.nhn` | ETF 전체 목록 + 시세·NAV·순자산 |
| `m.stock.naver.com/api/stock/{code}/integration` | ETF 총보수·1년수익·괴리율·배당 / 주식 PER·EPS |
| `m.stock.naver.com/api/stocks/marketValue/{KOSPI\|KOSDAQ}` | 시총 순 전종목 |
| `m.stock.naver.com/api/stock/{code}/finance/{annual\|quarter}` | 재무제표 |
| `api.stock.naver.com/stock/{SYMBOL}/...` | **미국 주식** (나스닥 `.O`, NYSE는 suffix 없이 심볼만) |
| `data.sec.gov/api/xbrl/companyconcept/...` | 미국 기업 원본 XBRL (현금·주식수·현금흐름) |

KRX 정보데이터시스템(`data.krx.co.kr`)은 세션이 필요해 쓰지 않는다. KONEX는 조회되지 않는다.

## 설계 — 경계를 지킨다

```
fetch_*.py  →  data/*.csv  →  app.py / 스프레드시트 / LLM
 (수집)         (경계)          (표시·분석)
```

`app.py`는 **표시만 한다.** 수집 로직이 UI에 들어가지 않는다.

1. UI가 죽어도 데이터 레이어는 산다
2. 나중에 다른 프론트로 바꿀 때 CSV만 읽으면 된다
3. 같은 CSV를 LLM에 그대로 먹여 분석시킬 수 있다
4. **정렬·필터·조건부서식이 필요하면 스프레드시트가 더 빠르다.** CSV는 UTF-8 BOM으로 저장해 엑셀에서 바로 열린다

개인 보유 내역은 소스코드에 넣지 않는다. `data/portfolio.csv`(git 추적 제외)에서 읽고, 없으면 샘플로 뜬다.

## ⚠ 데이터 해석 주의 — 실측으로 확인된 함정

**1. 총보수는 비용 지표가 아니다.** 위 참조. 같은 지수면 1년 수익률 차이를 본다.

**2. 이름 검색만으로는 변종이 섞인다.** "S&P500" 30종 중 24종이 커버드콜·레버리지·섹터·채권혼합이다.
`fetch_etf.py`의 `EXCLUDE` 리스트로 거른다. 새 변종이 나오면 추가해야 한다.

**3. 컨센서스(E) 컬럼을 신뢰하지 않는다.**
삼성전자 2026.12 컨센서스가 **매출 727조 · 영업이익 380조**로 조회됐다 — 2025년 실적의 2~9배로 비현실적이다.
→ **판정에는 확정 실적만 쓴다.** 추정치가 필요하면 1차 자료로 교차 확인.

**4. 네이버는 2차 가공 데이터다.**
빠르고 편하지만 원본이 아니고, **현금및현금성자산·발행주식수가 없다.**
→ 국내는 **DART**(`opendart.fss.or.kr`), 미국은 **SEC EDGAR**가 1차다.
특히 적자 기업의 **현금 런웨이**(= 유동성 ÷ 분기 소진액)와 **희석**(발행주식수 추이)은 네이버로 판정할 수 없다.
이 둘이 상장폐지 전 단계에서 가장 먼저 움직이는 지표다.
